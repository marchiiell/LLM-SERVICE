# LLM Service — FastAPI + LLM + RAG

Небольшой продакшен-ориентированный сервис вокруг LLM:
- чат со стримингом, кэшем, лимитом запросов и очередью к модели;
- **RAG**: загрузите свои файлы (`.txt`, `.md`, `.pdf`), и бот отвечает по ним со ссылками на источники;
- логирование, веб-страница с форматированием ответов, Docker.

Поддерживаются провайдеры **Gemini**, **Groq**, **xAI (Grok)** и **Anthropic (Claude)**. Без ключей сервис работает в режиме-заглушке, поэтому всё можно запустить и протестировать сразу.

## Провайдеры и ключи

Задайте **один** ключ, и провайдер выберется автоматически (`PROVIDER=auto`).

| Провайдер | Переменная | Где взять ключ | Бесплатно? |
|---|---|---|---|
| Gemini | `GEMINI_API_KEY` | https://aistudio.google.com/apikey | есть бесплатный уровень с лимитами |
| Groq | `GROQ_API_KEY` | https://console.groq.com/keys | есть бесплатный план с лимитами |
| xAI (Grok) | `XAI_API_KEY` + `MODEL` | https://console.x.ai | в документации бесплатного уровня нет |
| Anthropic | `ANTHROPIC_API_KEY` | https://console.anthropic.com | нет, нужны оплаченные кредиты |

Условия и лимиты бесплатных уровней меняются, проверяйте их на сайтах провайдеров. Модель по умолчанию можно заменить переменной `MODEL`.

Ключи храните только в переменных окружения или в файле `.env` (он в `.gitignore`). Никогда не публикуйте их в чатах, на скриншотах и в репозитории.

## Быстрый старт

```bash
python -m venv .venv
source .venv/Scripts/activate      # Windows (Git Bash); на Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
export GEMINI_API_KEY="ваш_ключ"   # необязательно: без ключа будет заглушка
python -m uvicorn app.main:app --reload
```

Откройте http://localhost:8000. Документация API: http://localhost:8000/docs.

## RAG: вопросы по вашим документам

1. Откройте вкладку **Документы** и загрузите файлы (для проверки есть `examples/sample.md`).
2. Вернитесь в **Чат**, включите галочку «Отвечать по моим документам» и задайте вопрос, например: «сколько запросов в минуту разрешено?».
3. Под ответом появится блок **Источники** с фрагментами документов, на которых основан ответ.

Как это работает:
1. Файл превращается в текст и режется на фрагменты по ~800 символов (по абзацам, с небольшим перекрытием).
2. **Гибридный поиск** выбирает самые подходящие фрагменты двумя способами и объединяет результаты (метод RRF):
   - **по словам (BM25)**: точные термины, названия, числа; простая обработка русских окончаний; работает всегда;
   - **по смыслу (эмбеддинги Gemini)**: находит близкое по значению, в том числе на другом языке. Русский вопрос найдёт английский текст лекции. Включается автоматически, если задан `GEMINI_API_KEY` (чат при этом может идти через Groq).
3. Найденные фрагменты передаются модели вместе с вопросом, а инструкция требует отвечать только по ним и ставить ссылки `[1]`, `[2]`.
4. **Режим обзора.** Если по вопросу ничего конкретного не нашлось (например, «помоги с лекцией»), модель получает начало документов, рассказывает, о чём они, и предлагает вопросы, которые можно задать. Если документов нет совсем, модель не вызывается.

Документы и их векторы сохраняются в `data/index.json` и переживают перезапуск. Чтобы хранить их только в памяти, задайте пустой `DATA_DIR`. Файлы, загруженные до включения поиска по смыслу, можно обработать кнопкой на вкладке «Документы» или запросом `POST /api/docs/reindex`. Если сменить `EMBEDDING_MODEL` или `EMBEDDING_DIMENSIONS`, старые векторы считаются устаревшими и пересчитываются той же кнопкой.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | статус, провайдер, модель, число документов |
| POST | `/api/chat` | обычный ответ целиком (с кэшем) |
| POST | `/api/chat/stream` | потоковый ответ (SSE) |
| POST | `/api/docs?name=файл.pdf` | загрузить документ (тело запроса — байты файла) |
| GET | `/api/docs` | список документов |
| POST | `/api/docs/reindex` | досчитать векторы (поиск по смыслу) для старых документов |
| DELETE | `/api/docs/{id}` | удалить документ |
| POST | `/api/ask` | вопрос по документам, ответ целиком + источники |
| POST | `/api/ask/stream` | то же потоком: первое событие `sources`, затем `delta` |
| GET | `/api/stats` | счётчики запросов, токенов, статистика кэша |

```bash
curl -s localhost:8000/api/chat -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Объясни RAG в двух предложениях"}]}'

curl -s "localhost:8000/api/docs?name=sample.md" --data-binary @examples/sample.md
curl -s localhost:8000/api/ask -H 'Content-Type: application/json' \
  -d '{"question":"сколько запросов в минуту разрешено?"}'
```

Если задан `SERVICE_API_KEY`, добавляйте заголовок `X-API-Key: <значение>`.

## Docker

```bash
cp .env.example .env     # впишите один ключ провайдера
docker compose up --build
```

Папка `./data` подключена как том, поэтому загруженные документы сохраняются между запусками.

## Что внутри и чему учит

| Файл | Тема |
|---|---|
| `app/llm.py` | единый клиент для провайдеров (OpenAI-совместимый API через httpx + Anthropic), стриминг SSE, ретраи с паузой, семафор как очередь |
| `app/rag.py` | извлечение текста, чанкинг, BM25, векторный поиск, объединение рейтингов (RRF), хранилище на диске |
| `app/embeddings.py` | клиент эмбеддингов Gemini: пакетная отправка, режимы документ/запрос, ретраи |
| `app/cache.py` | кэш одинаковых запросов: хэш от (модель, system, сообщения), TTL + LRU |
| `app/ratelimit.py` | скользящее окно, лимит на клиента, заголовок `Retry-After` |
| `app/main.py` | фабрика приложения, middleware с request id и таймингом, зависимости, SSE, обработка ошибок (429/502/503) |
| `app/static/index.html` | клиент на чистом JS: SSE через `fetch`, безопасный Markdown, загрузка файлов |
| `tests/` | pytest: API на режиме-заглушке, клиент провайдеров через `httpx.MockTransport`, RAG-модуль; без сети |

## Безопасность

- Текст документов считается данными, а не командами: инструкция модели прямо запрещает выполнять то, что в нём написано (защита от prompt injection хотя бы на базовом уровне).
- Ответы модели выводятся на странице после экранирования HTML, поэтому внедрить в страницу чужой код через ответ или документ нельзя.
- Размер загружаемых файлов ограничен (`MAX_UPLOAD_MB`).

## Ограничения (и куда расти)

- Поиск по смыслу требует ключа Gemini (у Groq, xAI и Anthropic эмбеддингов в этом проекте нет). Без ключа остаётся поиск по словам.
- Порог сходства `RAG_MIN_SIMILARITY` (по умолчанию 0.5) подобран на глаз: если находится слишком много лишнего, повысьте его, если слишком мало, понизьте.
- Векторы считаются в чистом Python и хранятся в JSON: этого хватает для сотен страниц. Для больших баз используйте векторную БД (Chroma, pgvector).
- PDF-сканы (картинки) не читаются: нужен OCR.
- Формулы LaTeX рисует библиотека KaTeX, которая загружается с CDN (jsdelivr). Без интернета в браузере формулы остаются обычным текстом.
- Кэш, лимиты и индекс хранятся в одном процессе. При нескольких воркерах или репликах вынесите их в Redis и векторную БД (Chroma, pgvector).
- Метрики простые; для продакшена подключите Prometheus и структурные JSON-логи.
- Идеи следующих шагов: оценка качества ответов (evals) на наборе вопросов, агент с инструментами, аутентификация по пользователям.
